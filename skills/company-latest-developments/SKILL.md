# Company Latest Developments（个股/项目最新进展）

当用户问"XX 最近有什么进展 / 最新动态 / 最近发生了什么 / 有什么新消息"时，
回答的骨架是**带日期的事件时间线**，而且每个关键事件要标注一手/二手来源。
不要只靠 news + web_search 拼凑：一手来源工具已经存在，必须先用。

## 取证顺序（在 search 定妥 symbol 之后）

1. `data_fetch sec_filings`：最近 90 天 SEC 申报索引（8-K/6-K/10-Q 等）。
   融资（可转债、增发）、并购、重大合同、管理层变动的**一手确认**在这里。
   引用时给出 formType + filingDate + 原文链接；模型记忆或媒体转述不能替代。
2. `data_fetch press_releases`：公司官方新闻稿。项目里程碑（开工、审批、投产）
   的公司口径以此为准。
3. `data_fetch analyst_actions`：带日期的评级/目标价动作流（grades +
   评级新闻 + 目标价新闻）。"机构怎么看"必须引用具体机构、日期、前后值，
   不要写"多家机构看好"这类无法核验的话。
4. `data_fetch news`（symbol 维度）：第三方报道补充时间线空档。
5. `web_search`：只用于以上一手来源覆盖不到的缺口——地方监管、社区听证、
   政府文件、行业媒体深挖（例如市政规划会、停工令、当地报纸）。搜索词带上
   具体地名/项目名和时间限定。

## 单份文件的性质判断

时间线之外，用户常常拿着一份具体文件问"这要紧吗"。两类最容易读反：

- **Form 4（内部人交易）**：取数入口是 `data_fetch(data_type="ownership")`——除机构持仓外，它还返回 `insider_statistics`（一段窗口内买入/卖出的笔数与金额汇总）和 `insider_trades`（逐笔明细：申报人与职务、交易方向、成交股数、成交价、交易后仍持有股数、申报原文链接）；`sec_filings` 只到申报索引，没有这两层。判"例行减持"还是"计划外卖出"落到四件事上：**是不是 10b5-1 预设计划**——结构化字段里没有这一项，要顺着明细里的原文链接看 Form 4 上的勾选框或脚注，是则卖出日期由计划决定、不携带择时信息，看不到就写"未核实是否属预设计划"，不要默认当成例行；**这笔占本人持股多少**——卖出股数 ÷（交易后持股 + 本次卖出股数），卖三成和卖九成是两件事；**同一窗口内是不是多名高管同时在卖**——把明细按申报人去重数人，一个人连续减持和五个人同月减持是两种信号；**同期公司有没有回购、有没有任何一笔内部人买入**——买入方向的信号强度高于卖出，因为减持还能用交税、行权到期和分散资产解释，增持不能。四项里取不到哪项就写明缺哪项；只报一个卖出金额和一句"高管在减持"就收尾，是这类问题最常见的错法。
- **S-3 储架登记**：**注册额度不等于已发行。** 未见实际发行时只写**上限稀释**（注册额度 ÷ 当前市值），并注明本轮未取到发行进度；不把它写成已经发生的摊薄，也不据此改 EPS、股本或合理价。要等 424B 招股补充或 8-K 给出实际发行价与规模，才转成已发生的摊薄。稀释比例、摊薄后 EPS 与合理价位移的算式按 `market_analysis`「事件 → 数字」那一节里股权融资 / ATM / 增发 / 可转债那一条，此处不重写。ATM 已在执行的，用公司披露的已售股数与均价，不用注册额度顶替。

## 输出纪律

- 主体是时间线：`日期 — 事件 —（来源：8-K 链接 / 公司新闻稿 / 媒体名）`。
- 一手（filings、press releases）与二手（媒体、博客）明确分层；只有二手
  来源的关键结论要标注"未见一手确认"。
- 悬而未决的事项（如审批是否通过、禁令是否解除）明确写"截至检索时间未有
  一手确认"，并说明下一个可观察节点（下次听证日期、财报日等）。
- 股价归因必须对齐事件日期与行情窗口；无法对齐时明确说不能归因。
- 结尾按仓位视角给一句"对持有者意味着什么"，遵循 hari-invest 的决策纪律
  （若已加载）。
