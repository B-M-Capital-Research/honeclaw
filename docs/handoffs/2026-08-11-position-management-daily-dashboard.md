# Hari 每日仓位管理建议仪表盘交接

日期：2026-08-11
状态：本地完成，未提交、未部署生产

## 结果

- 新增第 5 个首页 Button“仓位管理建议”，每日持仓新闻刷新后自动计算并保存 actor 隔离快照。
- 组合层展示已配置/未分配比例、最大持仓、前三大持仓、主题暴露和集中度。
- 个股层只输出“加仓候选 / 持有 / 降低暴露 / 立即复核 / 数据不足”，并展示结论依据、风险、证伪条件、逻辑编号、数据日期和来源。
- `hari-invest-v1` 的 `LOG-V0003/4/5/6` 与 HONE 自有集中度阈值分层记录；15%/25%/45% 不冒充 Hari 固定仓位比例。
- 只有当前行情、季度财务、复核后的当日估值、公司绿灯、当日宏观绿灯和无逻辑破坏新闻同时满足，才可能成为加仓候选。
- API 和页面均为只读；不会下单、调整仓位或声称执行。持仓变更后旧建议立即隐藏。

## 本地验收结论

- 使用含真实持仓的 authenticated local actor 验证了总仓位、未分配比例、最大持仓、主题暴露和高集中度状态；不在仓库文档中留存该 actor 的证券代码、成本或权重。
- 本地宏观不是绿灯；FMP 当前行情/季度财务和当日 Hari 估值未配置，所以所有缺证据持仓均正确显示“数据不足”。
- 展开任一持仓后可见成本（仅当前 actor）、估值未复核、新闻状态、低置信度、集中度预警、Hari 逻辑、风险与证伪条件；系统没有给出伪造的买卖动作。
- 未覆盖 ticker 保持“未覆盖/数据不足”，系统不会猜测或自动改写为其它 ticker。

## 风险与后续

- 生产必须配置可用的当前行情/财务源并提供每日已复核 Hari 三情景估值，否则“加仓候选”应继续为零。
- 宏观非当日绿灯时会抑制加仓候选；这是有意的失败关闭边界。
- 后续若接券商或自动交易，必须另立安全设计与用户授权，不得复用当前只读 API 暗中执行。
