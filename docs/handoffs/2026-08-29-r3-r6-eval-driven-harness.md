## 改了什么

### 一、C4：由已取字段驱动第二族（`valuation-audit`）

对账表补 EBITDA 行，并加一条**按已取字段咬**的规则：FCF 行 → FCF yield、EBITDA 行 → EV/EBITDA 或
EV/EBIT、营收行 → EV/S，各给下沿上沿两条算式与折每股口径；族仍由第三步按商业模式选
（资产持有型走 NAV，不套本条）。同时把「本轮只有一种方法」那个台阶**限定在分母确实取不到时**——
分母已在表里还只跑一族，不属于数据不全。补第三步的分部/SOTP 一行（逐分部「分母 × 倍数 = 小计」，
加总折每股要等于报出的那个数）。

### 二、C1：给非深度个股场景一个收口的去处

- `hari-invest` 资源路由表那一行去掉「**单独**」二字——q09 那种「护城河 + 现在影响股价的因素」
  同一轮问了两件事，原来的措辞把它排除在外；现在同轮还问了「影响股价 / 能不能买 / 值不值得 /
  还有没有空间」任意一项，就并载 `valuation-audit`。
- `moat`：点名护城河又带判断意味时，不要停下来问「要不要接着算估值」，直接按 `valuation-audit`
  第四步出下沿上沿与现价分位；**但只交这三样，不套它的终稿结构**（否则三只票要三张对账表，
  会把 q09 唯一得分的护城河那一维压薄）。
- `sector-to-stock`：估值列不能停在静态倍数。排序前三名按 `valuation-audit` 算出区间与分位；
  其余走机构口径（`targetLow/Median/High` 当低/基准/高价，标明「机构口径」，分档置信度按
  `analyst-coverage` 降一档）。表头保留「倍数」二字——`investment_response_guard.rs:7808` 的
  非现价词表靠它把这一列排除出现价一致性检查。
- `analyst-coverage`：隐含倍数换算不挑场景，报了目标价就要跟着做并和现价对上。
- `stock_research`:「X 技术分析」答完技术能力仍要给区间与现价位置。
- `etf-analysis`：每家先定公司类型再选倍数族；三个目标价来源是同一族的三个锚，不算跨族交叉。

### 三、异动题：连续四轮拿不到分的真正原因

`aaoi为什么突然大跌` 三轮分别 0.5 / 1.0 / 1.0，第四轮 0。四路诊断查清：

**机械检查没有误判**——iteration=3 的草稿真的违规（模型自述「the closing price for AAOI …
at $106.23, which represents a **-6.37%** decrease」，用了 provider 的 changesPercentage 而不是
服务端 `hone_change_basis.pct` 的 -6.22%，并把普通 quote 的 price 叫成 closing price）。
把线上正则跑在已发布终稿上，匹配数为 0。

真正的缺陷有三层，逐层修掉：

1. **纠正提示自己把答案封顶**。`market_move_final_correction_prompt_with_sources` 原文要求
   「重写一份**简短**终稿…正文控制在首行后约 **350 个汉字**…只写 **1—2 条**同日确定性因素…
   **不得写** Bull/Bear/Base Case、点位预测或交易建议」。而老王对异动题的标准是四步：
   ① 解释原因 ② **量化估值/股价影响** ③ 第一性原理看基本面与护城河 ④ **给应对**——
   ②③④ 正是它明令禁止的。改成「对原稿做定点修正、整篇输出、除被点名处外保留原意与篇幅」，
   并在函数上方留注释写明**不要把字数上限和禁令加回来**。
2. **`data_fetch` 的工具描述在教模型犯错**：「只有 quote/snapshot 时**一律写成「常规时段收盘价」**」，
   而收盘价检查恰恰拒绝这个写法。改成「最新可得的提供方报价（非逐笔）」，并写明要报收盘水平
   就取 `extended_hours` 的 session 汇总。
3. **那条原因段落检查对 Tavily 取证路径结构性不可达**。`current_turn_tool_result_urls` 会把
   `evidence_scope` 为摘要级的 `web_search` 消息**整条跳过**，而 `annotate_basic_search_evidence`
   对每一次成功的 Tavily 搜索都无条件写入 `full_page_content=false` / `kind="search_snippets"`——
   于是搜索来的 URL 一条也进不了采集，段落里引用 Tavily 链接时 `has_current_url` 恒为 false。
   这与日期锚点块（明确把 `web_search` 列为可用外检索并要求同段写出该链接）和 `web_search`
   自己的契约（`cite_same_result_url_inline=true`）直接打架。去掉这个跳过，证据强度仍由
   「该 URL 的结果记录本身必须覆盖目标日期」把关；配套给 `content_contains_date` 补上缩写月份，
   因为 Tavily 的 `published_date` 是 RFC-2822（`Fri, 28 Aug 2026 20:48:00 GMT`），原有 7 种写法一种都不匹配。
4. **违规文案不指出是哪一句**。修完 3 之后复测，三轮纠正的违规集**逐字相同**——模型被告知了规则，
   却要在三千字草稿里自己猜哪一处错。三条违规现在各自带上证据：涨跌幅那条引用本稿写的那个数
   和它所在的行；收盘价那条引用命中的原文；原因段落那条说清缺的是**三个条件里的哪一个**
   （同段没日期 / 同段没有本轮 URL / 引用的 URL 记录里没有目标日期），并给出段落开头。

`market_analysis` 同步把这些要求前移到生成时（服务端涨跌口径逐字用、普通 quote 不叫收盘价、
归因之后的三段、每个百分比紧跟自己的指标名、区间涨跌幅与当日涨跌幅分开写），
并厘清「归因题不输出买卖点」与「条件化应对」不冲突：第 8 条的若-则动作和第一段算出的
合理价位移照给。

   对账表「市值 = 现价 × 稀释股本」也不成立；q15 里「盘后 106.95」高于「收盘 106.23」却标 −6.22%。
   这类错误评分卡现在抓不到（它看结构不看验算），但用户会。
3. **C1 在 q10 / q11 / q12 / q18 / q20 仍是 0**。板块题的改动这一轮没体现在分数上
   （q11 仍 4 分：「六只票没有一个算出合理估值区间」），需要单独看是路由到了没执行，还是执行了被篇幅挤掉。
4. **market-move 那套机械检查本身仍是争议项**。两名独立审查按 `AGENTS.md` 138–158 行给出
   `crosses_line: true`：`is_market_move_final_check_enabled` 用 14 个词的关键词表决定是否启用整套检查、
   `paragraph_has_definitive_market_cause` 再用两张关键词表判定段落、原因段规则要求逐段证据映射、

   已经让它从「封顶答案」变成「纠正答案」。要不要继续留着，建议下一轮和你确认。
5. `skills/README.md` 生产端比仓库少 6 行（介绍 `company-thesis-ratings` / `hari-invest` 的那段，
   里面有一句「Local installation does not authorize … production deployment」）。
   安装脚本只投递 skill 目录、运行时也不读它，本轮未动；但这两个 skill 现在确实在生产上跑着，
   口径要不要改由你定。
