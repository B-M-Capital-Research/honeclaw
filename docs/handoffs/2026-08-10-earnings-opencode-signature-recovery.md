## Summary

After the OpenRouter account was recharged, the RKLB earnings-preview request progressed through evidence collection but failed with Gemini/OpenRouter `400 Corrupted thought signature`. The first repair added a narrow OpenCode earnings replay boundary and went live as `4dd76971`. The owner's first real canary then reached the renderer twice, but both reports were rejected before any write; a failed OpenCode built-in `glob` kept that otherwise safe trace outside the generic PDF-validation recovery predicate. The second repair extended only the dedicated OpenCode earnings predicate and went live as `185504bc`. Two subsequent NBIS attempts and an independent CRWV attempt proved that OpenCode's enabled `task` subagent both contaminated the replay-safety trace and could precede a new corrupted signature; they also proved that a clean retry discarded the already-converged report. Phase three in `2a6aecf3` denies `task`, continues an uncompacted native session twice, and carries the complete rejected draft plus exact renderer error into the one fresh isolated retry. A post-cutover CRWV canary then exercised the real signature-recovery path and completed with a persisted four-page PDF, closing the runtime recovery incident.

## What Changed

- Added a dedicated retry-safety classifier that accepts Hone's existing read-only calls plus exact OpenCode built-ins `read`, `grep`, and `glob`.
- Accepts OpenCode's `invalid` record only when its structured arguments explicitly prove `Model tried to call unavailable tool '<name>'`; the rejected target was never dispatched.
- Keeps real `bash`, `task`, ambiguous `invalid`, arbitrary external tools, executable skills, and persistent mutations outside automatic replay.
- The phase-one exception applies only to verified `opencode_acp` dedicated earnings turns. Ordinary conversations, other runners, context ownership, model routing and generic signature retry behavior are unchanged.
- Added an OpenCode-specific safe PDF-validation predicate. It accepts the same exact built-in read records while still requiring every renderer rejection to report `success=false`, `render_success=false`, `side_effect_status=not_started`, zero artifacts, and a nonempty validation error.
- The post-run persistent-effect normalizer now preserves this exact safe renderer failure so AgentSession can use its existing one-shot `fresh_session_after_safe_pdf_validation_failure` path. Real shell, unknown tools, completed/partial artifacts and uncertain results remain non-replayable.
- The isolated OpenCode config now explicitly sets `permission.task=deny`, matching the earnings skill's no-delegation contract. Exact rejected unavailable-tool records remain replay-safe, but an actually dispatched `task` remains unsafe.
- A required earnings run that ends normally without a PDF may receive up to two same-session correction prompts while OpenCode has not compacted. Each prompt includes the latest renderer error and reuses the native session's evidence/draft. A compacted session is never prompted again.
- If the bounded same-session path ends or compact already happened, the fresh isolated retry now receives the latest complete `report_markdown` from the renderer arguments and its bounded `render_error` as server-owned recovery material. The original persisted user message and prior chat history remain unchanged; drafts over 80,000 characters fail closed to the old recovery input.
