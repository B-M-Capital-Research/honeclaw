# Invariants

Last updated: 2026-08-29

## Source of Truth and Document Priority

- Code and tests take priority over explanatory documents
- `README.md`, workspace manifests, and `config.example.yaml` are the primary implementation-level docs
- `docs/repo-map.md`, `docs/decisions.md`, and `docs/adr/*.md` hold long-lived context
- `docs/current-plan.md` is the dynamic index, and `docs/current-plans/*.md` carries the state of individual tasks that still need tracking; neither file should carry long-term rules

## Definition of Done

- Relevant verification must be completed before a task is closed
- Any affected context documents must be updated before a task is closed
- Cross-module long-lived behavior changes or architecture decisions must be recorded in `docs/decisions.md`, with ADRs added when needed
- At the end of a medium-or-greater task, if the task needs handoff, pause-and-resume support, or explicit retention of follow-up risk, a handoff must be left behind

## Planning and Handoff Constraints

- Parallel tasks must not share the same detailed plan; each task should use its own `docs/current-plans/*.md`
- `docs/current-plan.md` only tracks active task links, status, and links
- `docs/current-plan.md` and `docs/current-plans/*.md` are opt-in: they only record cross-turn, cross-module, behavior / structure / workflow changes, or tasks that need parallel collaboration, handoff, or blocker management
- Low-value one-off tasks such as a single commit / sync / rebase, small script or config fixes, no-behavior-change patches, and pure copy or formatting changes should not be mechanically written into the dynamic plan docs
- For the same topic, prefer reusing the original handoff instead of adding fragmented files on the same day or in the same phase
- A handoff is not a logbook; keep only the goal, result, verification, risk, and unfinished items needed by the next person
- Small pure-execution tasks do not require a new handoff unless the user asks for one, the task needs asynchronous follow-up, or the task changes the workflow / structure / risk surface

## Testing and Script Constraints

- Rust unit tests should live next to the implementation in `#[cfg(test)] mod tests`
- Rust integration tests should live under `tests/integration/`
- CI-safe regression scripts should live under `tests/regression/ci/`
- Regression scripts that depend on an external account, an external CLI, or local machine state should live under `tests/regression/manual/`
- One-off troubleshooting scripts should live under `scripts/tmp/` and must not enter CI
- Open-source collaboration uses layered test coverage: prioritize core Rust logic, key cross-module paths, frontend state / data logic, and keep external integration verification split between local contract tests and manual regression
- Coverage numbers are secondary to behavioral proof; do not introduce a repo-wide `90%+` hard gate or optimize for static UI line coverage
- Default CI proof must cover Rust tests, frontend unit tests, and CI-safe regression scripts
- High-risk logic changes must keep success-path, failure-path, and boundary-condition verification in automated tests whenever the behavior is CI-safe

## Billing and Paid Access

- `billing_entitlements` is the only external paid-access truth source. Identity records, frontend state, Checkout return URLs, query parameters, email possession, and Discord roles cannot grant HONE access.
- Stripe is the only external Billing adapter. External entitlements are explicitly typed: `recurring_subscription` is keyed by Stripe Subscription ID and may receive bounded renewal grace after a prior payment; `fixed_term_purchase` is keyed by PaymentIntent ID, ends at its stored 12-calendar-month boundary, never auto-renews, and receives no grace. A user retains access while any independent Stripe entitlement grants access; duplicate recurring subscriptions remain separate rows, and an event for one reference or kind must never revoke another. Domestic invite access remains a separate identity authority.
- Stripe webhooks must verify the untouched raw body, enforce the configured mode/catalog boundary, persist an idempotent inbox event before processing, and reject stale state transitions. Inbox recovery uses bounded attempts and a lease whose completion is fenced to the claiming attempt, so an expired worker cannot overwrite a newer claim. Persist only a digest plus necessary normalized fields, never full payment-card data.
- A Stripe `checkout.session.completed` row is provisional and orders from the Checkout Session creation time, because the authoritative invoice/subscription events can have slightly earlier envelope timestamps and asynchronous wallet methods can complete Checkout before payment. First recurring access requires a paid Invoice; first fixed-term access requires a paid Checkout completion or async success for the exact configured one-time Price. Completed-but-unpaid, async failure, expiration, catalog/mode mismatch, and forged signatures grant nothing. A full Charge refund revokes only the matching fixed-term PaymentIntent entitlement; partial refunds do not mutate access. The inbox still preserves the real envelope time. Local CLI, registered test, and registered live webhook destinations each use their own signing secret; one runtime accepts only its configured mode/secret pair.
- Disabling new Checkout must not disable webhook ingestion or existing subscription management. Billing migrations are forward-only: the Stripe-only migration deletes retired-provider rows, replaces provider constraints, and keeps no dual-read or runtime compatibility layer.
- `/activate` follows the server's Stripe Checkout availability. When enabled it performs HONE email verification before server-created Checkout and permits only the server-owned `subscription` or `fixed_term` offer selector; the browser never supplies a Price, amount, currency, duration, or provider object ID. Alipay and WeChat Pay are one-time `mode=payment` methods only and must never be presented as subscription renewal methods. When Checkout is disabled or restore-only, the page permits login/restoration but offers no purchase action. Provider query parameters never select an alternate adapter.
- Stripe API key mode validation accepts same-mode standard (`sk_test_`/`sk_live_`) and restricted (`rk_test_`/`rk_live_`) keys and rejects every test/live mismatch. Production should use the least-privilege restricted key required by Checkout and Portal.
- Browser Checkout and Portal creation require an authenticated, same-origin request and server-owned catalog IDs. HONE iOS clients may log in and restore existing access but must not expose price or external digital-purchase calls to action.

## Investment Response Prompt Contract

- `soul.md` remains the complete investment-reasoning and answer-composition baseline restored from the pre-`71a4498e` large prompt. Refactors may move structural safety or caller-supplied typed scheduled/heartbeat enforcement into runtime code, but Interactive business prose remains Agent-owned and must not acquire a runtime semantic publication gate. No refactor may silently delete the prompt's time, entity, evidence, valuation, scenario, response-template, or anti-fabrication requirements.
- Every security, broad-market, and sector answer begins with a Beijing data-time and quote-basis line; no plan, greeting, heading, delimiter, or second time line may precede it. For open-ended Interactive turns, one live clock read creates both the Session context and the exact natural-DirectFinal answer-time anchor. On Web finance only, the service supplies exactly one typed, non-market-claim first-line contract using that Session time and the neutral basis `本轮仅使用可核验资料，具体报价时间与数据缺口在正文逐项披露`; the Agent's final body must reproduce it byte-for-byte. The complete Interactive answer stays behind `DeferredUserOutputEmitter` until one usable final exists: neither the typed line nor a model-authored header/body fragment may be ACKed early. The service may not synthesize a price, exchange, relationship, candidate, valuation conclusion, or any other open-ended market prose in the prefix, and may not semantically approve, repair, reject, or replace the completed body. Prefer `hone_quote_time.beijing` for quote-source time in the body; it must never replace the Session query time. `market_date_new_york` and generic `new_york` values prove only a market date/timezone, not NYSE, a close, or regular-session close. Exchange wording must come from structured `exchange` / `exchangeShortName` fields. Caller-supplied typed scheduled/heartbeat contracts retain their separate server-owned time/entity/quote prefix.
- Every nonempty interactive turn enters `AgentToolDiscovery`; the empty turn alone is `PassThrough`. This includes portfolio/watchlist wording: when membership matters, the main Agent calls actor-scoped `portfolio(view)` inside the same tool loop rather than a server phrase parser selecting a preflight route. Scheduled and heartbeat work may retain deterministic `Securities` / `Portfolio` / `Broad` preparation because their task body and execution contract are typed separately. Interactive requests must never stop at a server-side `confirmed no entity`, `needs clarification`, or phrase-grammar outcome before the main runner reads the complete current query.
- In the main agent loop, every named security discovered from the complete current request should receive its own current-turn `data_fetch(search)` call, including ordinary explicit tickers. Lowercase or mixed-case ticker spelling in a securities context still uses normalized exact-symbol lookup rather than alias ambiguity. The same Agent assigns a stable, distinct, case-sensitive `entity_route` to each named security, declares that individual search's call-scoped `identity_match=exact_symbol|name_or_alias`, and reuses the route verbatim on refinement, quote, profile/snapshot, and later DataFetch calls. Any identity search carrying an explicit route but missing a valid call-scoped `identity_match` is rejected before observer notification, registry execution, and provider/network access; it cannot inherit an older declaration or create/pollute ledger state. Independent calls may run in one parallel tool round, but multiple named entities must never be concatenated into one search query. Only a syntactically valid identity search may register a route; malformed, out-of-order, budget-rejected, or non-search calls never create or poison ledger state. An unknown alias whose returned symbol uniquely matches one accepted route is merged into that route instead of opening another. Interactive finance admits at most six identity routes for the complete turn, applies that limit while admitting the first batch, and rejects every later new route before execution. It instructs the Agent to prioritize user-named anchors before at most four screening candidates. Because the service does not infer semantic entity ownership from model-authored routes, this order-based ceiling cannot mechanically guarantee coverage when the user names more than six securities; the bounded final must disclose omitted coverage instead of expanding the crawl. Route-bound quote/profile/snapshot or other follow-up evidence is accepted only after that route's own valid search declaration and result. Before the structural floor permits `Auto`, every accepted route with candidates must have one same selected symbol in its route-bound quote and profile/asset-route evidence. Overlapping provider candidates, pre-search evidence, an unrelated quote, a mismatched profile, history, model memory, ranked-first results, scheduler metadata, another route, or partial provider output cannot establish it. This floor guides tool choice only and never gates a complete natural answer.
- Public chat must show what a pending turn is waiting on, in product language, beside the turn rather than inside the answer body. Tool status is named by tool kind — search, entity confirmation, market data, news, financials, holdings, reminders, analysis methods — and is derived from the runner label without any internal tool name, raw argument, symbol or provider detail reaching the browser. The pre-turn evidence pass runs before a runner exists and emits no tool status of its own, so the session emits its own start/finish stages around it; a silent window for the length of the enrichment budget is a defect, not a quiet success.
- Extended-hours evidence is session-window data, not a single price. `extended_hours` returns `hone_session_summaries` — per New York date+session open/close/high/low with the change from the previous window's close — alongside the latest bar, because a pre-market morning's latest bar cannot show the post-market drop the user is asking about. The pre-turn pass loads it whenever the regular session is closed (pre, post, overnight and weekends): the live-price freshness gate governs only whether the latest bar may act as a current price, and a completed session summary is never dropped for being hours old. Every Interactive discovery turn also carries a server-clock session alignment block — current Beijing↔New York mapping, the active session, what the regular quote's changesPercentage covers, and when `extended_hours` is mandatory — because the mapping is time arithmetic the server must do, not a fact the model should guess.
- Fundamentals are part of the answer, not a follow-up. `financials` returns the quarterly income statement, quarterly balance sheet and quarterly cash flow alongside the annual income statement, plus `hone_ttm` (the four filed quarters summed) and `hone_latest_quarter` (sequential change, year-ago change, gross margin, operating cash flow). The pre-turn pass loads it for every uniquely resolved security in the same parallel stage as the quote, because a turn that never holds the statements cannot discuss the business no matter how it is prompted. `hone_statement_coverage` names the statement that genuinely failed; a gap list must be derived from it, never from a fixed constant, or the turn will report evidence it is holding as unverified.
- A provider's trailing `eps`/`pe` is not a verified multiple. `hone_valuation_basis` compares it against `hone_ttm` and quarantines multiple claims when the provider window predates the latest filed quarter, which is precisely the window in which people ask about a print. The recomputed EPS and P/E travel with the quarantine so the answer can publish a correct multiple instead of omitting one.
- A comparison table is only as sound as its window. Companies on different fiscal calendars must be compared on `hone_ttm` (which carries gross and operating margin for exactly this reason) or on `hone_forward`, with the period ends printed. Placing one company's FY2025 beside another's FY2026 puts a full year of cycle position into one table, and every individual figure can be correct while the table is wrong. The same applies to multiples: a trailing P/E on a trough year beside one on a peak year compares nothing, so `hone_valuation_basis` derives `forward_pe`/`forward_ps` and the answer prefers those or a single trailing window.
- Forward multiples need a dated source, not arithmetic. `hone_forward` sums the four analyst-estimate periods dated strictly after the latest filed quarter — the reported window defines "forward", not a wall clock — and carries `min_analyst_count` so thin coverage is disclosed rather than averaged away. Fewer than four forward periods is not a forward-twelve-month estimate and is withheld. The multiple itself is computed server-side where the quote and the statements are both in hand; the model must not divide a current price by whichever EPS it happens to hold.
- Provider coverage gaps must not silently shrink the answer. When a named security is outside the provider's registry — a non-US listing, a symbol the registry does not carry — the turn may publish figures from current public search, but each one carries its source name,原始 URL and as-of date, is explicitly labelled as a public-source measure rather than a provider quote, never enters the `数据时间：`/`行情口径：` first line, and is never placed in the same column as provider quotes without that distinction. Dropping the security or answering 无法核验 is not an acceptable substitute for a disclosed, attributed figure.
- Daily investment dashboards must degrade by evidence class, not by fabrication. A provider outage may fall back to an exact-symbol official quote source or to bounded title-matched search snippets, but a quote cannot become a financial statement, a search snippet cannot become full-page or primary evidence, and neither may create an eligible valuation. Source facts are persisted before optional LLM enrichment; model failure cannot erase them. Every portfolio symbol must expose a coverage state, while incomplete financial/valuation evidence can only produce low-confidence hold/review/reduce actions and never an add candidate.
- Provider capability is declared, not discovered from wrong answers. Aggregate data types are rows in `stable_bundle_components` — a key and a path each — fetched concurrently by one generic bundler that reports `available` / `empty` / `unavailable` per component and surfaces per-component errors. Adding a capability must not require another hand-written join or another coverage map; that cost is why earlier gaps were closed one endpoint at a time, each after a user hit it.
- Published metrics beat recomputed ones. Trailing ratios, enterprise value, ROE/ROIC, leverage and liquidity come from the provider's own TTM endpoints rather than being derived from statements; Hone's own derived windows exist to cross-check a provider aggregate's freshness, not to replace its published figures. Scores that carry standard thresholds — Altman Z, Piotroski — must travel with their bands and their applicability limits, because a bare 2.4 forces the model to supply a threshold from memory.
- A comparison needs an anchor the model did not choose. Peers come from the provider's own classification with a batch quote and an industry P/E snapshot, never from the model's recollection of who competes with whom; segment revenue by product and by region answers where the money comes from; multi-period price change and the provider's own aftermarket quote ride along with the snapshot instead of costing a research round.
- Unit arithmetic belongs to the server, not to prose. Provider money and share-count fields are raw integers; `hone_display` renders them once into Chinese magnitudes (万 / 亿 / 万亿) with the listing's own currency, and the answer copies that string. One power of ten is invisible in a sentence — a 45.57bn market cap published as 4557 亿 reads as plausible and changes every conclusion drawn from it. Rounding that reaches 10000.00 of a unit is promoted to the next magnitude, because "10000.00 万" reads as 一亿.
- One search in the user's language is not coverage. The pre-turn search runs before the registry has resolved anything, so it can only use the user's own words and reaches only the coverage written in that language. Once an identity is confirmed the turn searches again under the standard symbol, the registry's company name and the New York trading date. Without this, a Chinese question about a US listing is answered from whichever same-day Chinese article exists, and a dominant English-language story never surfaces at all.
- Causal attribution needs breadth before confidence. A day usually carries several distinct stories — community opposition, an analyst action, a short disclosure, an earnings preview — and a single source naming a single cause may not be published as the core reason. The answer states which search angles ran, lists the other same-period items found, and when only one source supports a cause says so explicitly instead of converging on whichever article was read first.
- Perceived latency is a separate defect from latency. A section switch is instant, but a lazily-loaded route pays for its chunk on first click and a page that blanks itself for a round-trip reads as a hang; both are fixed where they occur, not by making the work faster. Route chunks are warmed on pointer entry and focus, and a page that already knows its data paints from cache and revalidates behind the visible content. Any cached session state must be cleared on sign-out and on a failed revalidation, or the cache paints a signed-out visitor as signed in.
- Work the user cannot see reads as a hang. The pre-turn pass issues roughly twenty provider calls before the first token; it reports stages as it goes — identity being verified, then the securities whose quotes, statements and valuation basis are being read — and the caller drains those updates concurrently so they surface while the work is still running. Stage details are server-authored but still reach the browser, so only characters that can occur in a ticker or company name survive, bounded in length.
- A refresh must not make a running turn look amnesiac. The run registry keeps the stages a turn has already passed through, de-duplicated and capped, so recovery rebuilds the visible trail rather than the single newest line; heartbeats prove liveness and never append a stage of their own. The registry lives in the serving process: a restart therefore reports the turn as interrupted rather than showing a thinking card that can never finish. The answer itself does not depend on any of this — the run is spawned independently of the response stream, every push ignores send failures, and the turn is persisted by the session layer whether or not a client is still listening.
- One run per conversation is deliberate. A second concurrent run would write the same conversation from two places, so starting one is refused with a stated reason rather than queued or silently dropped.
- A shared deadline turns one slow call into total evidence loss. The pre-turn pass budgets each phase separately: identity resolution gates everything after it and fails fast on its own clock, and every evidence branch — quotes, extended hours, statements, valuation, identity-anchored search — is bounded individually, so a slow provider degrades that branch to "nothing fetched" while everything already returned still reaches the turn.
- A design token that nothing defines fails silently. `var(--hone-thing, #fallback)` parses, renders and looks deliberate while ignoring the theme entirely, so a surface written against a vocabulary that does not exist stays frozen at its fallback — which is how a survey heading ended up at a contrast ratio of 1.01 in dark mode. Every referenced `--hone-*` name must be defined somewhere, and that is checked rather than reviewed.
- No vocabulary decides what counts as a security. Scheduled and heartbeat scans keep every structural candidate; the ones nothing in the sentence binds to a security are marked tentative, which prevents a deterministic contract and hands the request to the same Agent discovery the interactive path uses. Erasing candidates from a hand-kept acronym list looked safe and silently deleted eleven real listings — ARM, NOW, ON, AA, BE, IT, BB, AS, OR, GOOD, BULL — because a common English word and a ticker are the same string. An explicitly bound subject still settles, so scheduled work that names its security keeps its deterministic contract.
- The theme is a user preference, not an OS query. The palette flips by redefining tokens under `[data-theme="dark"]`, so any surface built from tokens themes itself; a surface that keys off `prefers-color-scheme` instead ignores the user's explicit choice and can render dark inside a page they set to light. Only the preference resolver reads the OS, and it does so to resolve `auto` — which is the default, so a first visit follows the system exactly as the interface language already does.
- Restraint in the answer contract governs claim strength, never coverage. No instruction may trade breadth for brevity: whatever the current tool results support — session, trend, sequential and year-ago comparisons, margins, cash flow, balance-sheet structure, valuation basis, catalysts, risks — is expected in the answer with concrete numbers when relevant to the question, and only genuinely missing measures are disclosed as gaps. The research budget is sized for this: identifying a security is not the same as explaining one.
- Every Interactive turn gets one service-side evidence pass before the first model call: an open `web_search` on the user's own words under a real provider recency window (`time_range`), anchored on the absolute Beijing date and, when they differ, the target market's local date as well — a Beijing morning is still the previous New York session, so a Beijing-only anchor points at a US date that has not happened yet. A date inside the query text is only a ranking hint; recency must reach the provider as a constraint, and it stays opt-in on the tool so definitional and historical questions are not stripped of authoritative older sources. The pass also runs, plus `data_fetch(search)` for each scanner candidate and a `snapshot` for any candidate the registry resolves to exactly one symbol. The results enter the turn input as context and nothing else — they never build a contract, fix an entity, constrain the answer, or replace the Agent's own tool work. Provider errors and registry misses contribute nothing; the stage is bounded by a wall-clock deadline and degrades silently to an ordinary Agent-owned turn rather than delaying or failing the user. Because this evidence lives in the turn input rather than in `tool_calls_made`, the request carries `preloaded_evidence_calls`, and the evidence-free publication precondition stands down when it is nonzero.
- Interactive entity seeds are advisory candidates, never a vocabulary decision. The scanner no longer consults maintained acronym, metric or grammar-word lists: `CTA`, `PE`, `CPI` and `ARR` reach the Agent as low-confidence candidates and are dismissed by a real registry lookup, which is the only thing that can separate `nbis`/`isrg` from `hi`/`stock`. Removing those lists also restored recall the lists were destroying — `how about AAPL`, `what do you think about NVDA` and `NVDA 的 PE 是多少` previously produced no seed at all. Code-shape is judged structurally (upper case, adjacency to non-ASCII text, or being the whole query), and the guarantee that remains is that an Interactive turn never closes into a deterministic `Securities` scope. Typed scheduled and heartbeat work resolves seeds into a contract with no Agent reading the request, so it keeps one consolidated deterministic brake; removing that too requires routing scheduled entity resolution through the same Agent loop.
- The lexical scanner owns audited bare/cashtag/exchange-qualified/share-class/index/crypto-pair spans and syntax and delegates provider dialect/canonical equivalence to the shared `hone-core::provider_symbol` truth source, but its Interactive output is only a non-factual candidate seed. It cannot declare the entity set complete, trigger clarification, or prevent the main Agent from finding names, aliases, mixed identifiers, or unusual wording. The service must not infer entity boundaries or match mode by splitting commas, `and`, `和`, `&`, `/`, share-class text, case, length, or ticker shape; AT&T, S&P Global, M&T Bank, H&R Block, BRK/B, and `Berkshire Hathaway, Class B` remain for the Agent to understand from full context. The Agent's first `exact_symbol` declaration fixes a persistent route constraint, using only audited provider equivalence; later name refinement cannot replace CRWV with an embedded-name product such as CWY. `name_or_alias` grounding preserves word boundaries for short names such as Ford, Apple, and Tesla. A later successful search under the same `entity_route` replaces earlier empty/noisy candidates and resets the current empty-attempt streak. Untagged legacy searches form provisional per-query routes and remain active alongside tagged routes until an explicit search names one exact, case-sensitive old query through the actual `query`, `refines_query`, or `supersedes_query`. `refines_query` and `supersedes_query` are strictly mutually exclusive; if both appear, no provisional route migrates and the explicit route remains pending. A valid single-source migration carries only search/empty attempt history, verbatim query aliases, and an already Agent-declared exact-symbol constraint; it never imports candidates, quote symbols, profile/asset-route symbols, or post-identity attempts. One tagged entity must never hide all untagged entities. A route still empty after two current consecutive search attempts requires a real route-correct non-search attempt after the latest empty result before bounded disclosure; an unscoped no-symbol follow-up may be assigned only when exactly one active route exists. Amounts, years, percentages, cadence, target prices, and metric/technology acronyms remain excluded as lexical securities. The blocking auxiliary-LLM JSON extractor and its timeout/failure result are not part of current-turn entity discovery.
- For interactive turns, the Agent reads the complete query and its observed tool trace—not a service-side keyword list—determines which evidence is loaded into context. The service must not infer “quote-only”, “valuation”, “recent analysis”, “extended hours”, or a required response template from user wording. It may observe deterministic current-turn boundaries for telemetry, but those observations cannot authorize publication or change a successful body. It must not parse arbitrary Agent-authored financial, holding, news, event, or valuation chapters, prepend facts, normalize prose, continue omitted seeds, retry/repair the answer, rewrite content, or reject success. One canonical answer/session-history/SSE terminal remains mandatory; typed scheduled/heartbeat contracts retain their separate deterministic validation and fallback path.
- Interactive function-calling output keeps model-authored tool-capable prose speculative behind `DeferredUserOutputEmitter`. Every nonempty request may use the open Agent tool loop, but only a budget-accepted current-turn DataFetch call with a registered tool name, supported `data_type`, all required targets, valid identity shape, and parseable arguments activates finance guidance. Unsupported/missing-target/malformed/rejected DataFetch retains ordinary answer semantics. Active finance research stays in one `Agent::run`, one context, and one model role across Web, Feishu, Discord, and Telegram. Provider requests use the composed current input plus at most four prior user utterances / 4,000 characters, spending that budget newest-first and labelling it as reference-only; they exclude historical assistant/tool/reasoning facts. Production exposes only real actor-bound business tools: it has no `finish_research`, completion handoff, source catalog, locator correction, separate terminal synthesizer, terminal audit, post-answer semantic review, or second generation. Finance research has intrinsic ceilings of three tool-call batches, 24 total calls, 20 DataFetch calls, and six Web calls even when the caller supplies no tighter budget. At the first exhausted ceiling, the next request in the same Agent loop has `tools=[]` and asks that same Agent to form one natural evidence-bounded final from the existing context; this is the ordinary next iteration, not the retired second terminal generator.
- A tool that owns one store must never let its result read as an answer about every store. `cron_job` owns cron/heartbeat jobs only; event pushes and daily digest slots live in notification prefs and survive `remove_all`. `list` and `remove_all` therefore carry `automatic_push` with `all_automatic_push_stopped` and the named `remaining_sources`, `remaining_count: 0` means zero cron jobs and nothing more, and no service-authored confirmation or model answer may state that automatic reminders are off unless `all_automatic_push_stopped` is true. An actor who never set `digest_slots` is on the system default schedule and is still being pushed.
- A research answer must hold current-turn evidence before it can be published, and the trigger is structural rather than lexical. The answer contract requires an investment answer to open with the exact `数据时间：北京时间 …；行情口径：` line and to omit that format entirely otherwise, so the header is the Agent's own declaration of what it is publishing. A final carrying it in a turn that executed no business tool is withheld for one bounded retry with `Required` tool choice; blocked-batch turns keep their own safety finalization and are excluded. This covers listing denials, IPO and private-company wording, fabricated prices, multiples and target prices, and evidence-free refusals with one rule and no claim vocabulary. Where evidence does exist, contradiction checks match it by symbol and by provider company name — both taken from the payload, never from a maintained word list.
- Identity resolution may never consume the whole turn. Identity-only DataFetch `search` rounds draw on a separate two-round budget instead of the three substantive research rounds, the last two global tool-call slots inside the bounded finance loop are reserved for `web_search`, and a per-tool or reserve rejection is not budget exhaustion while open research still has budget. If the research budget is reached and the turn executed no business call other than identity searches, the loop must not emit a tools-disabled final: the same Agent gets one bounded open-research round with the identity registry removed from the tool list and an instruction to research what the user actually asked. A finance turn that ends with zero substantive evidence attempts is treated as a defect, not as a bounded outcome, because its answer is indistinguishable from an offline model's.
- The request-local structural ledger records only accepted Agent-declared identity routes, their current candidates, bounded empty attempts, route-bound quote/profile/snapshot, broad-market, symbol-scoped, and crypto `search → crypto_quote` paths. Before the structural floor, business tools use `Required`; afterward the same real tools use `Auto`, allowing another tool call or one natural nonempty `Stop + Done` DirectFinal. The ledger, route ceiling, and tool ceilings constrain research work and produce telemetry; they do not semantically approve, replace, suppress, or rewrite a complete answer. Once finance is active, every batch must name tools in the active registry and be classified for effect. Any unknown, unregistered, persistent, write-capable, or otherwise effect-uncertain call keeps the complete batch outside assistant framing, observer notification, registry execution, and network access. When every call is registered and known read-only, structurally validate each call independently: a malformed call remains zero-execution and auditable while its valid read-only siblings continue. Non-executable `skill_tool` prompt loading is known read-only; `execute_script=true` remains write-capable.
- Keep all matching current-turn tool results in the same Agent context. DataFetch search remains identity-only; quote/profile/financial/relationship facts require their own current evidence. Web output is bounded snippet evidence, not a page body or ranking. Relationship direction and strength must stay within current evidence; absent direct support, use neutral wording and do not elevate a relationship to core/largest/major customer or supplier, high dependence, locked/exclusive/priority status, multiple binding, ownership/non-ownership, GPU model, contract value, or equivalent detail. Genuine missing coverage is disclosed narrowly and never widened into a fixed whole-answer refusal.
- Current listing status is a current-turn structured fact, not a model-memory judgment. DataFetch `snapshot` and `earnings_outlook` expose `hone_security_listing_evidence`; `active_listing` requires provider-equivalent requested/quote/profile symbols, a positive current quote, a nonempty structured exchange, and profile `isActivelyTrading=true`. ## Notification Delivery Constraints

- Notification digest slot labels are actor-visible semantics, not decorative metadata. When `quiet_hours.to` coincides with a configured digest slot, the quiet flush must merge into that slot and reuse its label; it must not silently replace a named “盘前/盘后” digest with the generic “晨间静音合集”.
- Actor-scoped deterministic notification controls—timezone, named digest slots, quiet hours, generic/directional price thresholds, price-ladder repeat step, and the large-position boundary—must use the validation and atomic patch contract in `hone-event-engine::prefs`. Agent tools and HTTP APIs must not maintain divergent range, time, overlap, or kind-tag validation. A conversational request that changes interdependent quiet/slot fields or a price threshold plus its repeat step together must use one composite patch, not sequential writes that validate against stale intermediate state.
- Price-alert execution and explanation have one domain truth source: `NotificationPrefs::effective_price_alert_policy`. Router dispatch, `notification_prefs.get_overview`, the admin schedule API, and every UI summary must resolve system candidate bands, actor thresholds, the non-large-position floor, large-position exception, repeat step, and inheritance provenance through that policy. The effective overview must also disclose every higher-priority gate that can change the outcome: the system event-engine switch and global disabled kinds can stop execution entirely; the per-category daily High cap applies to price alerts; the ordinary same-symbol cooldown explicitly does not apply to intraday price bands. Raw nullable overrides are not a truthful substitute for the effective policy. `immediate_kinds=price_alert` must not bypass an explicit price threshold.
- PricePoller candidate bands and actor notification ladders are separate layers. The poller may emit only `candidate_first_pct + N * candidate_step_pct`; an actor threshold between candidate bands becomes observable at the next candidate band, and any user-facing forecast must report that actual grid instead of promising unavailable precision. Within each actor/symbol/direction/day lane, a band is immediate only after the first effective threshold and after advancing by at least the actor's effective repeat step; insufficient advances and same/lower-band oscillations are not additional immediate pushes.
- Nullable actor overrides have explicit inherit semantics. A delivery patch distinguishes `Keep`, `Inherit`, and `Set`; for digest slots specifically, `None` means inherit global slots, `Some([])` means disable digest, and `Some(slots)` means use the complete actor-owned slot list.
- The ordinary `notification_prefs` Agent tool may expose deterministic time and numeric controls, but it must not expose free-form prompt, model, classifier, or investment-mainline fields. Its published JSON Schema must describe the array/object/number/null values that execution actually accepts.

- `AgentSession` exposes `run()` as the only public entry point; its responsibilities should stay limited to session orchestration, persistence, and listener dispatch. When adding a new execution path, prefer extending the unified runner contract instead of adding a new `run_xxx` branch.
- Shared execution preparation belongs in `crates/hone-channels/src/execution.rs`; session flows and transient task flows should reuse it instead of each path rebuilding tool registry / runner / sandbox wiring on its own
- Runner selection and provider / CLI differences belong in `HoneBotCore::create_runner()` and `crates/hone-channels/src/runners/`; do not reintroduce provider-specific checks in channel entrypoints or `AgentSession`
- Heartbeat and other transient scheduler tasks may bypass transcript persistence, but they must still reuse the same execution-preparation path instead of directly instantiating concrete runner types inside `scheduler.rs`
- A channel actor's local file visibility must stay inside a repo-external actor sandbox. The default root lives under `hone-agent-sandboxes/` in the system temp directory; `HONE_AGENT_SANDBOX_DIR` may override it only when the resolved path is outside the current source checkout / git worktree.
- Actor sandboxes must not contain portfolio storage files. - 用户可见的运行进度允许保留执行细节，但如果文案中包含 actor sandbox 内的绝对路径，必须改写为相对 sandbox 根目录的路径；sandbox 外绝对路径不得原样透出

Generic `Internal error`, timeout, authentication/permission failure, transport close, stderr text, or a missing-rollout detail naming any other ID must fail the turn; none may silently create a replacement or resend a prompt.

## 用户调研问卷

- 问卷是无登录入口，因此绝不落原始 IP 或 User-Agent，只落 `sha256(salt + ":" + client_key)`。盐来自 `HONE_SURVEY_DIGEST_SALT`，多副本部署必须显式设置——每个副本各自生成盐会让 24 小时去重完全失效。无盐的 IP 哈希不是匿名化：整个 IPv4 空间可在数秒内枚举。
- `client_digest` 不属于 `SurveyResponse`，任何读取路径都不可能把它带到前端；这一点由测试锁定，不能靠调用方自觉。
- 题库只在前端定义，后端只做结构校验（键的字符集与长度、题数、选项数、类型）。后端不认识任何选项文本，所以改题、加题、调整选项都不需要动后端与数据库。超长开放题截断而不是拒绝——一段认真写的长回答不该整条丢失。
- 提交限流分三层：同 IP 冷却、进程内每小时配额、按摘要的落库计数。只有最后一层跨副本且能在重启后存活，前两层是快速拒绝而不是保证。落库计数失败时放行并记 warn，不能因为计不了数就丢掉一个正常用户的回答。
- 问卷页面上对隐私的承诺与实现是同一件事的两面：改动存储行为时必须同步改 `CONTENT.survey.privacy`。

## 投资决策大脑：存储合同指标边界

- NBM/RPO、订单/积压、协议数量、收入增长、产品收入或位元占比必须分别保存；任何一项都不能被别名、模型摘要或确定性投影替代另一项。
- 存储 NBM RPO 必须保留合同覆盖的终端市场、已开票/未开票状态、预计确认期和可终止/保护条款。范围含 Edge 时不得写成纯数据中心订单；RPO 不等于收入、现金、不可取消保证或估值。
- 公司/SEC 一手财务事实可以进入待复核证据层；未完成不可变人工复核的财务观察不得进入每日评级动态因子，也不得绕过七日内至少两种方法的三情景估值门槛。

### 隔离转换实现登记不等于代码执行

- 只有当前独立批准的转换规范可以登记一个 create-once、内容寻址实现；同一批准不得覆盖、重复或分叉登记。
- 实现必须精确绑定全部上游哈希，并冻结工件、代码 revision、split/feature 算法版本、serializer、输入输出 schema 和静态资源边界。
- 登记记录不得拥有 callable entrypoint、环境继承、环境变量、密钥、网络、外部工具、子进程或生产读写能力。
- `registered_not_run` 只允许进入独立实现复核；不得生成 manifest/bundle、join 特征、定义 target、训练、奖励、影子、订单、券商或交易。

### 隔离转换实现复核不等于 runner 登记或执行

- 独立复核人必须排除完整上游角色和实现登记者；复核链必须追加式、自哈希、精确绑定前序和当前实现。
- 审计必须独立复现工件摘要并重新验证代码 revision、split/65 项 feature 实现、canonical serializer、固定 schema 与单 subject/2048 MiB 资源上限，不能只信任登记器字段。
- 可批准的唯一结果是未来隔离 runner 规范登记资格。runner、执行授权、执行、manifest/bundle/join、target、training、reward、shadow、order、broker、trading 必须继续为 false。

### 隔离转换 runner 登记不是执行授权

- runner 规范必须 create-once、内容寻址并绑定当前有效的实现独立批准、实现和完整上游；状态只能为 `registered_not_run`。
- runner 登记人不得属于数据集、治理、转换规范、规范复核、实现或实现独立复核的完整角色链。
- 工件 SHA-256、不可变代码版本、固定运行时身份/版本、只读输入、内容寻址 create-once 输出和静态资源上限必须进入自哈希记录，不得由运行时覆盖。
- `callable_entrypoint_registered`、首次执行授权、环境继承/变量、密钥、网络、工具、子进程、生产读写与历史修改必须为 false。
- 唯一下一门禁是独立首次执行授权复核。manifest/bundle/join/target/training/reward/shadow/order/broker/trading 必须继续为 false。
- 角色重合、绑定漂移、工件或合同不一致、沙箱能力打开、复核链分叉/循环/篡改均失败关闭。

### 隔离转换首次执行授权复核不是 claim 或执行

- 复核链必须按精确 runner ID 隔离、追加式、自哈希并绑定唯一前序；读取时必须拒绝分叉、循环、断链、前序哈希漂移、重复或文件名不匹配。
- 复核者必须排除 runner 登记者和数据集、治理、转换规范、规范复核、实现、实现复核及此前授权复核完整角色链；排除集必须进入哈希并按链重建。
- 批准必须同时复现 runner 工件摘要并确认代码可复现/工件可用、只读输入与根文件系统、非特权/no-new-privileges、create-once 内容寻址输出、独立输出校验、固定资源，以及无环境、密钥、网络、工具、子进程、生产或历史状态能力。
- 批准最多授予提交后 24 小时内的一次未来隔离调用资格。授权记录不得 claim、消费、调用、执行或创建输出；过期或已 claim 必须失败关闭。
- output validation、manifest/bundle/join/target/training/reward/shadow/order/broker/trading 必须继续为 false；下一门禁只能是独立实现的单次执行尝试。

### 隔离转换一次性执行结果不是正式训练制品

- 只有当前、未过期、未 claim 且完整绑定可重开的授权可以进入调用；运行制品摘要必须在 claim 前重新验证。
- claim 必须先 create-once 落盘；claim 后成功、明确失败或只有 claim 的中断都永久消费授权，同一 runner/授权不得重放。
- 转换只能读取精确封存数据集和封存快照；不得联网、调用工具、读取宿主环境/密钥、启动子进程或写生产/历史状态。
- 同公司、历史重建、行情快照或来源身份的传递连通分量不得跨 split；边界只按冻结时点顺序和整数目标决定，250 交易日 purge/embargo 后任一分区为空必须失败关闭。
- 无确定点时值的 65 项 allowlist 特征必须显式缺失，不得补值、插值或使用结果/标签/未来信息；封存留出标签必须隐藏。
- 输出只可标记为 `untrusted candidate envelope`；official manifest/bundle、join、target、training、reward、shadow、order、broker、trading 必须保持 false，下一门禁只能是独立输出校验。

### 独立转换输出校验通过仍不是正式 manifest 或 feature bundle

- 校验者必须排除执行调用人、runner 登记/授权复核人、完整上游、数据集装配及正式标签链角色；一个 attempt 最多形成一条 create-once 校验记录。
- 校验必须重开精确当前数据集、封存行情和 runner，并允许按历史精确哈希审计已过期/已消费授权；不能只依赖 ID 或执行层内存对象。
- 独立校验算法不得调用执行层转换函数。连通分量必须用不同实现重算，并重新验证边界、250 日 purge/embargo、65 项显式缺失来源、排除审计、留出隔离和 canonical output SHA-256。
- 任一结构、绑定、角色、哈希、权限位或重算差异必须写入不可变失败记录并失败关闭；不得人工覆盖为通过。

- validator 必须排除 Stage 132 executor、Stage 131 claimant 与 Stage 51–132 完整责任链；每个 Stage 132 receipt 只能写一个 create-once、append-only、自哈希终态，失败不得覆盖或改换 validator 重试。
- 验证必须使用服务端派生路径重新打开 exact Stage 131 claim、Stage 132 result、receipt manifest 与每个加密内容对象；逐项重算 result/manifest/ciphertext 摘要、长度、只读常规文件保管和完整责任链。
- 独立实现必须自行派生 nonce/AAD，执行 AES-256-GCM 认证解密，并重算明文长度、SHA-256、内容地址、格式 magic、安全结构、敏感字段和 receipt 脱敏证据。不得调用 Stage 132 的接收/筛查 helper 代替验证。
- 缺失、格式错误或指纹不匹配的密钥必须在创建终态前失败，允许修复运行配置；manifest、密文、认证解密、明文或责任链漂移必须形成失败终态。
- Stage 133 通过只证明加密 receipt 的完整性和保管链，不证明其中持仓数字真实。通过只开放 Stage 134 零能力物化实现登记；不得解析金融行、物化/准入快照或创建 financial allowlist、ledger、position、cash、NAV/performance、model/training/RL/reward、order/broker/trading 权限。

## Stage 134 期初快照物化零能力实现登记边界

- registrar 必须排除 Stage 133 validator、Stage 132 executor、Stage 131 claimant 与 Stage 51–133 完整责任链；记录必须 create-once、自哈希，并精确绑定当前 validation、result、claim、receipt 与 Stage 125 specification。
- 登记只能冻结未来确定性 PDF/CSV/JSON parser/materializer 合同。当前必须没有 decryption key/input read、receipt plaintext、parser/runtime、output write、candidate snapshot 或 authoritative snapshot 能力。
- 未来 schema 必须完整覆盖账户、现金、持仓、上市期权、负债与未结算活动；金额和数量必须是精确十进制字符串和有符号数量，禁止 binary float。证券身份优先级、公司行动对账和成本基础规则必须固定。
- 每个输出行必须绑定来源工件 SHA-256 和可重放来源位置，且不得携带真实账户号、凭据或 secret。缺失、歧义、不支持资产、部分账户、手填、默认或推断必须令整份快照失败关闭。
- 对账单市场价值只能作为信息字段，不得直接产生 NAV/绩效。未来输出只能是 create-once、untrusted candidate，并须经过独立输出验证和独立准入。
- Stage 134 只开放 Stage 135 责任链外独立实现复核；不得创建 financial allowlist、ledger/event、position/cash、NAV/performance、model/training/RL/reward、order/broker/trading 权限。

## Stage 135 期初快照物化实现责任链外独立审查边界

- reviewer 必须排除 Stage 134 registrar、Stage 133 validator、Stage 132 executor、Stage 131 claimant 与 Stage 51–134 完整责任链；每个实现只能产生一个 append-only、终态、自哈希审查记录。
- 独立审查不得调用 Stage 134 builder；必须用第二实现重建 10 个固定函数和完整合同，重算 Stage 125/131/132/133/134 哈希与绑定，并逐项重新验证 Stage 134 的 18 项确认。
- 完整账户、现金、持仓、上市期权、负债、未结算活动、精确十进制、有符号数量、证券身份、公司行动、逐行来源和缺失/歧义/不支持/部分/默认/手填/推断整批失败语义必须再次失败关闭。
- Stage 135 不接收 key、receipt 字节、路径、明文或解析结果；没有输入读取、解密、parser/runtime、输出、候选/正式快照或任何财务、训练和交易权限。
- 明确批准只开放 Stage 136 隔离物化器规格登记；changes-required 或 rejected 均终止当前链，必须从新的 Stage 134 登记重新开始。
