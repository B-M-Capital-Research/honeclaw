## 端到端链路

1. 用户在 Feishu direct 中提交新的持仓结构，要求更新记录。
2. assistant 先把新结构写入或声明已更新，但保留了旧持仓。
3. 用户进一步明确“只有这些股票，其他没有了”，这是清空旧持仓的高确定性指令。
4. assistant 后续账户分析仍读取或沿用旧持仓 `QCOM / INTC / GLW`。
5. 最终账户健康度、总市值、浮盈亏和操作建议均被旧持仓污染。

## 期望效果

- 当用户明确说“以我的记录为准，只有这些股票，其他没有了”时，持仓上下文应把未列出的旧股票清除或至少在写入前确认清除范围。
- 后续账户分析必须只使用用户刚确认的持仓集合；如果 `BE` 只是候选买入，应单独作为“未持有 / 待确认”处理。
- 如果持仓持久化工具不能执行清空旧记录，应明确告诉用户未完成清理，而不是继续基于旧记录分析。

## 当前实现效果

- assistant 没有遵守用户对持仓全集的纠正，继续把旧持仓当作当前账户组成。
- 回复对 `GLW / QCOM / INTC` 生成浮盈亏、风险判断和财报操作建议，导致账户健康度结论与用户最新输入不一致。
- 这不是单纯措辞问题：它影响持仓记录、账户分析和后续投资建议的正确性。

## 用户影响

- 用户明确更新后的账户画像仍被旧数据污染，可能据此做出错误的加仓、减仓或止损判断。
- 该问题会削弱持仓记录链路可信度，并可能影响后续定时任务、画像和投研上下文。
- 定级为 `P2`：这是 Feishu direct 主链路中的数据上下文 / 持仓语义错误，但当前证据集中在单个会话，未见跨用户错投、敏感数据泄露、批量数据破坏或全渠道不可用，因此不升 `P1`。

## 根因判断

- 初步判断是持仓更新工具或 prompt 层只处理“新增 / 更新本轮提及标的”，没有把“只有这些股票，其他没有了”归一为清空未列出旧持仓的操作。
- answer 阶段可能继续从旧 persistent portfolio 或 compact summary 中读取 `GLW / QCOM / INTC`，且没有以当前用户最新全集声明覆盖旧上下文。
- 该问题不同于 `feishu_direct_etf_holding_wrong_entity_write.md`：那是模糊指代导致写错 ETF；本单是用户已经明确全集后，旧持仓仍未被清理。
- 该问题也不同于 `feishu_direct_followup_loses_recent_entities.md`：本单不是丢失上一轮实体，而是旧实体优先级过高并污染最新持仓全集。

## 下一步建议

1. 为 Feishu direct 持仓更新增加回归：用户给出持仓全集并说“其他没有了”后，后续分析不得出现未列出旧标的。
2. 在持仓工具层支持显式 `replace_all` / `clear_missing` 语义，或在无法确认时要求用户确认将删除哪些旧持仓。
3. 在 answer 阶段加入最新用户持仓全集覆盖规则，避免 compact summary / persistent portfolio 旧记录压过当前 turn。
