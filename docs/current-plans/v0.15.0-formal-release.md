## Goal

Publish the current `main` as `v0.15.0`, including synchronized version metadata and bilingual release notes, an annotated Git tag, a GitHub Release, a Universal macOS DMG, and the repository's supported iOS Simulator/Xcode artifacts.

## Scope

- Audit `v0.14.1..HEAD`, the clean worktree, remote parity, Apple client build contracts, and release automation.
- Bump all workspace, Tauri, and Xcode marketing versions to `0.15.0`.
- Refresh the architecture poster for the new release because the Agent runner architecture changed after `v0.14.1`.
- Run the release baseline plus targeted Agent/channel/Web/Apple client validation.
- Push the release commit to `main`, create and push annotated tag `v0.15.0`, and monitor the tag-triggered Release workflow until the GitHub Release and expected assets are complete.
- The repository intentionally publishes an unsigned/ad-hoc Universal macOS DMG and an unsigned iOS Simulator app plus Xcode source archive. A device IPA/App Store archive is outside this release because this host and CI do not have an Apple Developer signing identity or provisioning profile.

## Risks / Open Questions

- This Mac currently exposes Command Line Tools rather than full Xcode and has no valid Apple code-signing identity. The tag-triggered `macos-14` workflow is therefore the authoritative Apple build environment.
- The Universal macOS DMG remains ad-hoc signed unless repository secrets are expanded to Developer ID/notarization credentials.
- The iOS deliverable is a Simulator `.app` and Xcode source archive, not a device-installable IPA; producing an IPA requires Apple Developer signing and provisioning that are not configured.
- The Release workflow also updates the Homebrew tap and must be monitored through completion rather than treating a pushed tag as completion.
