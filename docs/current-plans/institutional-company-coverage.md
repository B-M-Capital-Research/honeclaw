## Goal

把 Hone 从“识别到财报并发一条摘要”，提升为“替每位用户持续维护少量重点公司的研究纪律”：

1. 重大事件发生时，先及时说明事实和未知项。
2. 随后把新信息与该用户原有投资主线、关键因子、估值假设和风险条件逐项比较。
3. 财报电话会、10-Q / 10-K / 8-K 和后续经营数据出现后，继续补齐而不是另起一条孤立消息。
4. 把本季尚未回答的问题带到下季，形成可审计的长期跟踪记录。
5. 任何投资主线或估值假设的正式变化都由用户确认；Hone 可以提出修改草案，但不能静默代替用户改观点。

本计划不以“把每条推送写得更长”为目标。完成标准是：用户能在两分钟内知道“发生了什么、相对我的预期哪里变了、对长期主线有什么影响、下一步要核验什么”，并能在下一季度看到这些问题被继续追踪。

## Institutional Benchmark

### 机构共同做法

本计划借鉴的是机构的研究运营方式，而不是照搬卖方长报告：

- CFA Institute 把关键因子的筛选建立在重要性、投资期限、可预测性和市场共识可预测性上，并要求研究形成差异化判断、估值、催化剂和事后复盘。
- Capital Group 强调分析师跨越多年和不同周期了解公司，并由股票、债券和私募研究人员互相挑战假设。
- Baillie Gifford 使用稳定的问题框架反复审视公司的长期增长空间、竞争优势、文化、资本配置、上涨空间和“市场遗漏了什么”；其公开流程还包含周度公司讨论、月度组合讨论和季度风险复核。
- S&P 的公开研究方法把季度更新、重大事件、评级变化和持续的一手材料更新视为常规覆盖，并给出了每家公司每年约 7–8 次正式更新的历史运营基准。这个数字只作为覆盖密度参照，不直接成为 Hone 的产量 KPI。
- SEC 将 10-K、10-Q、8-K、proxy 和 insider filings 作为研究公司的核心原始披露。Hone 的关键事实必须回到这些材料或公司正式披露，不能把新闻摘要当最终事实源。

### 对 Hone 的取舍

机构可以让一名分析师覆盖约二十家公司，并配套模型、委员会和合规复核；个人投资者不需要复制这套人力结构。Hone 应保留其中最有价值的五件事：

1. 限定覆盖范围，少而深。
2. 先登记预期和证伪条件，再看结果。
3. 明确区分事实、解释、判断和行动。
4. 把未决问题和管理层承诺跨季度带下去。
5. 定期主动挑战原主线，避免系统只替用户寻找支持证据。

## Product Decision

### 1. 从“消息流”改为“公司覆盖制度”

每位用户对一家公司只能有一份持续演进的 `公司覆盖簿`。财报、电话会、SEC 披露、行业变化和价格异动都是这份覆盖簿的输入，不再各自成为没有上下文的孤立摘要。

覆盖簿至少包含：

1. **覆盖理由**：为什么持有、观察或暂不参与；预期持有期。
2. **投资主线**：用户目前认为价值将由什么驱动。
3. **关键因子**：真正能改变判断的 3–5 项经营变量，而不是无限指标列表。
4. **预期基线**：本季和未来 1–3 年的关键指标、公司指引、市场共识和用户自己的假设；拿不到的数据必须标为未知。
5. **差异化判断**：用户认为市场漏看、错定价或尚未确认的内容。
6. **估值情景**：悲观、基准、乐观三种情景及关键假设，不强制给单一目标价。
7. **风险与证伪条件**：什么事实出现后应削弱或推翻当前主线。
8. **管理层承诺台账**：谁在何时承诺了什么、验证日期、当前状态和实际结果。
9. **催化剂与观察日历**：财报、产品、监管、客户、产能和行业节点。
10. **未决问题与决策记录**：还不知道什么、何时应有答案、用户为何改变或维持判断。

### 2. 覆盖分级

不是所有 ticker 都值得同等深度：

| 等级 | 对象 | 服务承诺 |
| --- | --- | --- |
| A 核心覆盖 | 主要持仓或用户指定的最高优先级公司 | 完整覆盖簿；重大事件即时快报；财报深度复盘；电话会补充；月度例外检查；季度主线复核 |
| B 观察覆盖 | 观察名单、潜在建仓或次要持仓 | 重大事件与季度复盘；只有触及预设关键因子时主动升级 |
| C 发现池 | 临时提及、行业候选或低优先级公司 | 保留基础事实和来源；不自动生成重研究，用户升级后再建覆盖簿 |

默认先让用户选择少量 A 级公司。没有画像或主线的公司，系统应明确说“尚未建立你的判断基线”，先帮助建档，而不是伪造个性化结论。

### 3. 财报采用三层交付

#### 第一层：即时快报——先知道

目标是在正式披露出现后快速回答六件事，建议控制在手机一屏到两屏，而不是一句话：

1. 公司发布了什么，财季和来源是什么。
2. 最重要的 2–4 个数字，以及分别相对市场预期、公司指引和用户基线的差异；缺一项就明确写缺失。
3. 哪一个用户关键因子被强化、削弱或尚无法判断。
4. 最大的反向证据或风险，不能只挑好消息。
5. 当前还缺什么材料，例如电话会、10-Q、分部数据或现金流细节。
6. Hone 何时、根据什么材料继续更新。

即时快报只在信息确实重要时主动推送；后续材料若只是补充细节，更新同一研究卡并进入摘要，不连发多条打扰用户。

#### 第二层：事件研究卡——看懂这一次

在财报新闻稿、8-K / 10-Q 等正式材料可得后形成一张完整研究卡：

- `结论`：主线增强 / 基本不变 / 需要观察 / 明显削弱，并标注置信度。
- `预期差异表`：实际值 vs 市场共识 vs 公司指引 vs 用户基线 vs 上季 / 同期。
- `关键因子逐项核验`：每项给事实、解释、反证和状态。
- `经营质量`：增长来自量、价、组合、并购还是会计口径；利润是否转化为现金。
- `管理层执行`：本季兑现了哪些旧承诺，新增了哪些承诺。
- `估值影响`：哪些假设需要重算，暂不直接替用户给买卖结论。
- `未决问题`：电话会或下季必须回答的问题，以及预计验证时间。
- `证据`：每个关键事实的原始来源、发布日期和截至时间。

#### 第三层：公司覆盖簿——跨季度记住

电话会、正式季报和后续经营材料出现后，Hone 更新同一事件研究卡，并提出覆盖簿修改草案：

- 新事实可以自动入时间线和证据记录。
- 关键因子状态可以自动建议变化，但需保留前值和理由。
- 投资主线、估值假设、证伪条件和覆盖等级只能在用户确认后正式修改。
- 本季未决问题必须自动带入下一次财报的预先检查表，直到被回答、作废或由用户关闭。

### 4. 长期研究节奏

| 节奏 | 核心动作 | 用户应看到的结果 |
| --- | --- | --- |
| 首次覆盖 | 建立主线、关键因子、反方观点、估值情景和证伪条件 | 一页覆盖卡，而不是公司百科 |
| 财报前 T-7 至 T-1 | 回顾上季承诺与未决问题，登记本季预期 | “本次最该验证的 3–5 个问题” |
| 财报 T0 | 即时快报 | 事实、差异、主线影响、未知项、跟进时间 |
| 正式材料可得后 | 事件研究卡 | 完整差异表和关键因子核验 |
| 电话会 / transcript 可得后 | 管理层与未决问题复核 | 哪些问题已回答、哪些承诺需要跨季追踪 |
| 每周 | 只处理触发关键因子的例外事项 | 无重大变化时不为了活跃而推送 |
| 每月 | A 级覆盖簿健康检查 | 画像是否过期、哪些问题逾期、是否缺反方证据 |
| 每季度 | 主线、估值和风险复核 | 用户确认维持、修改、降级或退出覆盖 |
| 每年或重大转折 | 从零重写一次反方论证 | 防止旧主线因惯性永久保留 |

### 5. 以 SNDK 为试点时的正确形态

以下只展示产品结构，不代替对本次财报的重新核验：

- 不能只写“营收增 372%、毛利率升 58ppt、消费端环比降 32%”。
- 应先调出该用户已经登记的关注点，例如 AI 数据层、企业级 SSD / hyperscaler 采用、NAND 供给纪律和估值风险。
- 快报要逐项说明：数据中心订单和毛利改善分别支持了哪条主线；消费端下滑削弱了什么；增长中有多少来自价格、销量、组合或低基数仍未知。
- 电话会后继续补：企业级 SSD 客户和订单能见度、NAND 供给纪律、资本开支、毛利可持续性、消费端库存是否需要重新设定预期。
- 下季财报前自动带回这些问题，并核对管理层本季承诺是否兑现。

## User and Hone Responsibilities

### Hone 负责

- 搜集并标明一手事实、来源和截至时间。
- 把同一事件的新闻稿、SEC 披露、电话会和后续数据合并到同一研究卡。
- 做实际值与多重基线比较，暴露缺失数据，不用空白臆测结论。
- 提出投资主线、关键因子、风险和估值假设的修改草案。
- 记住管理层承诺、未决问题和下次验证日期。
- 主动呈现与用户主线相反的证据。

### 用户负责

- 决定哪些公司进入 A / B / C 级覆盖。
- 确认自己的投资期限、主线、关键因子和估值假设。
- 确认是否修改长期主线、证伪条件或组合行动。
- 对“继续持有 / 加仓 / 减仓 / 退出”等投资决策保有最终责任。

## Scope

### 当前实施切口（2026-08-06）

- 将 earnings release 探测从仅早晚摘要前拉取，调整为美股常见财报发布窗口内的高频探测，并以权威披露实际可得时间记录时效。
- 扩充财报质量合同：完整保留关键证据、反向项、未知项和下一次核验问题；即时消息不再只显示一句总结。
- 即时财报消息按 actor 读取该 ticker 已蒸馏的投资主线；没有主线时明确提示尚未建立用户基线。
- 把同一财报新闻稿型 8-K 降为摘要材料，避免它与结构化财报快报连续双推。
- 扩充新建公司画像模板和跟踪元数据，使 A / B / C 覆盖等级、投资期限、预期基线、估值情景、管理层承诺和决策记录成为正式研究资产。
- 本切口完成后先跑 SNDK 结构化回归与跨渠道渲染验收；24 个历史样本和一个完整财报季仍属于后续阶段，不在单次代码变更中伪造完成。

### 第二切口进展（2026-08-06）

- 状态：`done locally`；总计划仍为 `in_progress`。
- SEC 财报新闻稿与结构化财报卡现在使用统一的规范化文档身份；无论哪一条先到，成功交付后同一 actor 都只保留结构化财报卡，摘要缓冲中的 SEC 兜底会被移除，之后到达的同文档 SEC 事件会被审计为 `superseded`。

### 第三切口进展（2026-08-06）

- 状态：`done locally`；总计划仍为 `in_progress`。
- 在用户授权的 `$20` OpenRouter 上限内，用生产 SEC 摘抄器、同一财报研究 prompt 和同一 JSON 合同真实比较了新旧多代模型；模型目录按 OpenRouter 当日 `created` 字段重新筛过，最终优先考虑 2026 年 5–8 月的当前代模型。
- 旧 Grok 4.3、DeepSeek V3.2 以及重复运行的 DeepSeek V4 都出现过美元 B/M 与中文“亿”之间的 10 倍数量级错误；Kimi K2.5、Qwen 3.5/3.8 出现截断或空 JSON；OpenAI、Google、Anthropic 路由被上游 TOS 403 拒绝且未绕过策略重试。
- 用户明确偏好 Grok。综合 SNDK、AMD、BE 三份真实样本，默认财报质量 profile 已切到 2026-07-08 发布的 `x-ai/grok-4.5`；最后一轮三份均保持结构完整和数字单位正确，单份实测估算成本 `$0.01150–$0.01511`，平均约 `$0.01309`。
- 财报复核是每家公司/每次事件一次的共享事实成本，不按订阅用户数重复。按每家公司每年 4 次财报，20/100/500 家公司的毛估分别约 `$1.05/$5.24/$26.18`；加 20% 重试余量约 `$1.26/$6.28/$31.41`。
- 研究 prompt 新增硬约束：优先原样保留 `$8.97B`、`$226.4M` 等单位，不擅自换成“亿美元/万元”；非 EPS 指标缺少 actual/estimate 时不得写“全面超预期”。真实赛马累计消耗约 `$0.252`，远低于授权上限。
- AMD 最后一轮 Grok 置信度为 `0.86`，在现有 `0.90` 即时门槛下会进入摘要。因为当前真实样本均为强正面财报，本切口没有为追求更多即时推送而下调门槛；必须补入混合/负面样本后再校准。

### 第四切口进展（2026-08-06）

- 状态：`done locally`；总计划仍为 `in_progress`。
- 画像跟踪现在与持仓共同形成订阅：A 级覆盖完整 symbol 事件，B 级覆盖财报、transcript、SEC、重大新闻与公司行动且不以 High 打断，C 级只做财报发现。观察公司不再因为没有持仓而漏掉财报。

## KPI Framework

### 北极星指标

**重大事件研究闭环率**：A 级公司发生重大事件后，在承诺时限内同时完成以下四项的比例：

1. 有来源的即时快报。
2. 与用户主线和关键因子明确对照。
3. 正式材料 / 电话会出现后的同卡补充。
4. 未决问题和管理层承诺进入下一次验证清单。

试点目标：`≥ 85%`；正式扩大覆盖前目标：`≥ 90%`。

### 驱动指标

- A 级覆盖簿完整率：`≥ 90%`，且每家公司只有 3–5 个真正关键因子。
- 用户主线关联率：A 级公司即时快报 `100%` 明确写出增强 / 不变 / 待观察 / 削弱；没有有效主线时必须写“缺少基线”。
- 连续性兑现率：下一个适用披露中，`≥ 90%` 的旧承诺和未决问题被重新核对，不得静默消失。
- 原始证据覆盖率：`≥ 95%` 的关键事实能定位到公司正式披露、SEC 文件或可核验的一手材料。
- 决策有用率：用户对“是否帮助我理解变化并决定下一步研究动作”的评分中，`≥ 80%` 为 4/5 或 5/5。

### 时效指标

时效从权威材料实际可得时开始计算，不从传闻或日历预期时间计算：

- 即时快报：中位数 `≤ 10 分钟`，P90 `≤ 20 分钟`。
- 正式材料研究卡：中位数 `≤ 90 分钟`。
- transcript / 电话会材料可得后的补充：中位数 `≤ 2 小时`。

信息不完整时允许准时发布“已确认事实 + 明确未知项”，不得为了看似完整而臆测。

### 护栏指标

- 重大事实错误、错误归因或无来源关键数字：`0`。
- 未经确认静默修改用户主线或估值假设：`0`。
- 同一事件重复即时推送率：`< 2%`。
- A 级公司通用模板冒充个性化：`0`。
- 只有正向证据、没有反向证据或未知项的深度复盘：`0`。

## Validation

### 验收样本

在进入真实试点前，使用至少 `24 个历史财报事件` 做盲测：

- 至少 6 个来自用户实际关注的公司，且 SNDK 必须包含在内。
- 覆盖盈利成长、亏损成长、周期、成熟现金流四种公司类型。
- 至少 8 个样本包含财报电话会或 transcript。
- 至少 6 个样本存在“标题很好但经营质量有明显反向项”的情况。
- 至少 4 个样本存在指引变化、会计口径变化或低基数导致的表面高增长。
- 同一家公司至少连续覆盖 4 个季度，用于检查承诺和未决问题是否真正跨季保留。

当前证据边界：仓库 fixture 已覆盖 SNDK、AMD、BE、SNOW、COST、MU 六种 archetype 各四个连续季度，24 个来源均为唯一 SEC exhibit，并完成生产 prompt 的付费回放。它尚未加入 transcript，也尚未由不知道生成过程的人类评审者评分，因此只计为“自动链路与连续性合同通过”，不计为本节完整盲测过关。

### 评审量表

每个样本由不知道系统生成过程的评审者按 0–2 分打分：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 事实可靠 | 关键事实错误或无来源 | 基本正确但来源 / 截至时间不完整 | 关键事实可核验，口径和时间清楚 |
| 预期比较 | 只报同比 / 环比 | 与一种基线比较 | 同时区分市场、公司和用户基线，缺失项明确 |
| 个性化 | 通用总结 | 提到用户关注点但未形成判断 | 逐项对应用户主线和关键因子 |
| 反方与未知 | 只写利好或武断结论 | 有风险提示但较笼统 | 有最强反向证据、未知项和验证方式 |
| 连续性 | 与上季无关 | 引用部分旧问题 | 完整核对旧承诺并生成下季清单 |
| 决策用途 | 看完仍不知道下一步 | 有泛化建议 | 清楚说明主线状态和下一步研究动作 |
| 表达效率 | 冗长或过短失真 | 可读但重点不稳 | 两分钟内读懂，深度材料可继续展开 |

单样本满分 14 分。历史盲测的通过线：平均 `≥ 11 分`，任何样本的“事实可靠”不得为 0 分；SNDK 及另外两家 A 级试点公司的连续四季样本平均 `≥ 12 分`。

### 个性化对照验收

对同一家公司、同一份财报，构造两位拥有不同投资主线的测试用户：

- 原始事实部分必须一致。
- 主线影响、风险优先级和下一步问题应随用户画像合理不同。
- 没有画像时必须降级为通用事实卡并提示建档，不能猜测用户关注点。
- 任何一个用户的私有主线不得出现在另一个用户的输出中。

### 连续性验收

以连续四季材料逐季回放：

1. Q1 写下的每个管理层承诺和未决问题，都必须在预计验证期到达时重新出现。
2. 已回答、被证伪、过期或用户关闭的项目必须保留结论和理由。
3. Q4 的覆盖簿应能还原全年主线如何变化，而不是只剩最新一季摘要。
4. 删改用户主线必须有用户确认记录，不能由事件摘要间接覆盖。

### 通知体验验收

- 同一财报事件默认最多一条即时推送；后续研究卡和 transcript 更新同一对象。
- 只有新增信息足以改变主线状态或触发证伪条件时，才允许第二次主动提醒。
- 快报必须包含明确的跟进承诺，例如“等待电话会后补充客户集中度和供给纪律”。
- 用户从即时快报进入研究卡后，应直接看到完整预期差异和自己的关键因子，不需要重新搜索公司。
- 无重要变化的每周检查不得制造“为了活跃而推送”的内容。

### 上线关卡

阶段一进入阶段二必须同时满足：

- 24 个历史样本达到量表通过线。
- 三家 A 级试点公司的覆盖簿完整率达到 90%。
- 个性化对照、跨季连续性、来源隔离全部通过。
- 重大事实错误和静默主线修改均为 0。

阶段二进入阶段三必须同时满足：

- 完成一个完整财报季或至少 3 个真实财报事件的前瞻闭环，以较晚者为准。
- 重大事件研究闭环率达到 85%。
- 用户决策有用率达到 80%。
- 重复即时推送率低于 2%，且没有用户确认的重大打扰案例。
- 用户明确确认扩大覆盖，而不是系统因处理能力足够就自动扩大。

### 明确判定为失败的情况

- 快报比现在更长，但仍没有和用户主线、预期或上季承诺比较。
- 同一家公司对不同用户输出完全相同，却声称已经个性化。
- 研究卡只有利好和泛化风险，没有最强反方证据与未知项。
- transcript 作为新消息另发，却没有回答此前登记的问题。
- 本季提出的问题到下季静默消失。
- 用点击率、消息数量或模型评分代替用户决策用途和事实可靠性。
- Hone 未经用户确认修改了长期主线、估值假设或证伪条件。

## Risks / Open Questions

1. **用户主线尚未结构化。** 先从少量 A 级公司共创覆盖簿；没有基线时宁可明确降级，也不伪个性化。
2. **市场共识或细分 KPI 不一定可得。** 允许缺失，但必须暴露缺失来源和影响；不得用同比增速替代“超预期”。
3. **个性化可能强化确认偏误。** 每次深度复盘固定加入最强反方证据和“若从零开始是否仍建立该主线”的检查。
4. **公司覆盖过多会稀释质量。** 先限制 A 级公司数量，达到连续性和事实护栏后再扩展。
5. **短期价格波动容易绑架长期研究。** 价格反应作为市场反馈，不自动等同于基本面结论；只在它揭示预期差异时进入主线分析。
6. **旧提案偏工作台实现。** `auto_p1_earnings-lifecycle-workbench.md` 保留为能力层参考；本计划是更上位的产品与研究运营合同，后续实现必须先满足本计划再选择页面和数据形态。
7. **验收人力。** 历史样本可先由 Hone 生成结构化评分材料，但最终“是否反映我的主线、是否有决策用途”必须由用户确认，不能由模型自评替代。
